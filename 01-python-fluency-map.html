1.1

Core Language Mechanics

Backbone
comprehensions*args / **kwargsclosuresdecoratorsfunctools.wrapsdataclassesEnum / StrEnum
Mental modelEverything an agent touches is either a dict you reshape or a function you pass around.

Agent state, messages, and tool I/O are all nested JSON-shaped dicts. A tool registry maps names → functions, and decorators (@tool, @retry, @cache) wrap behavior everywhere. This is the fabric all higher layers are woven from.

TOOLS = {}

def register_tool(fn):
    TOOLS[fn.__name__] = fn          # name -> callable
    return fn

@register_tool
def get_weather(city: str) -> str:
    return f"sunny in {city}"

# an agent dispatches a tool by its STRING name + a kwargs dict:
result = TOOLS["get_weather"](**{"city": "Singapore"})
DrillExtend the registry above so @register_tool also captures each function's docstring & signature (via inspect) into a schema dict — the seed of a tool definition.
Common mistakes
  • Mutable default args (def f(items=[])) share state across calls — default to None.
  • Decorators without functools.wraps silently lose the wrapped function's name & docstring — which breaks auto-generated tool schemas.
  • Closures capture variables by reference — a loop building lambdas all see the final value (late binding).

Async / Await

Backbone · the non-negotiable core
async def / awaitevent loopasyncio.gatheras_completedSemaphoreasync forasync withtimeoutsQueue
Mental modelAsync doesn't make code faster — it stops you wasting wall-clock waiting. Ten API calls that each take 1s finish in ~1s, not 10s.

Agents are I/O-bound — almost all wall-clock is spent waiting on API responses. Concurrency is where every bit of your speed comes from, and every serious framework is async-first underneath. One accidental blocking call freezes the entire loop.

import asyncio, random

sem = asyncio.Semaphore(3)              # at most 3 calls in flight

async def call(i):
    async with sem:                     # rate-limit concurrency
        await asyncio.sleep(random.random())   # NOT time.sleep — that blocks!
        return i

async def main():
    tasks = [call(i) for i in range(10)]
    for coro in asyncio.as_completed(tasks):    # results as they finish
        print(await coro)

asyncio.run(main())
DrillWrap each call() in asyncio.wait_for(..., timeout=2) and collect results with gather(..., return_exceptions=True) so one timeout doesn't kill the batch.
Common mistakes
  • A bare time.sleep() or requests.get() inside async def blocks the whole event loop — use asyncio.sleep / httpx.AsyncClient.
  • Forgetting await — the coroutine is created but never runs; you get a "coroutine was never awaited" warning.
  • gather() cancels its siblings on the first exception unless you pass return_exceptions=True.

Type Hints + Pydantic v2

Backbone · highest-leverage library in the whole step
list[str] / X | NoneLiteralTypedDictBaseModelField(description=)field_validatormodel_dump / validatemodel_json_schema()ValidationError
Mental modelA Pydantic model is the contract between your code and the LLM — the same class defines the tool schema going out and validates the data coming back.

Pydantic is the bridge between Python and tool use. The JSON Schema an LLM sees for a tool is frequently auto-generated from a Pydantic model via model_json_schema(). Structured outputs, tool arguments, and config objects are all Pydantic models in modern stacks. If you learn one library deeply before frameworks, make it this one.

from pydantic import BaseModel, Field
from typing import Literal

class WeatherQuery(BaseModel):
    city: str = Field(description="City name")   # description is SENT to the LLM
    units: Literal["c", "f"] = "c"

schema = WeatherQuery.model_json_schema()        # <- this is the tool's input schema
q = WeatherQuery.model_validate_json('{"city": "Tokyo", "units": "c"}')  # parse + validate
DrillPrint the model_json_schema() above, then feed model_validate_json a string with a bad units value and handle the ValidationError cleanly — this is exactly how you'll guard real tool calls.
Common mistakes
  • Pydantic v1 vs v2 APIs differ (.dict()→.model_dump(), .parse_raw()→.model_validate_json()) — tutorials mix them; use v2.
  • Field(description=...) text goes to the model — write it as an instruction, not a code comment.
  • Any-typed fields skip validation entirely — avoid them in tool schemas.

Mental modelTreat the model's text output as almost-JSON, never quite — always parse defensively.

LLMs wrap JSON in prose or code fences and occasionally emit broken JSON. You'll write extraction & repair logic constantly and traverse deeply nested payloads without it becoming spaghetti.

DrillWrite extract_json(text) that finds & parses the first balanced {…} block in a string surrounded by prose, raising a clean custom error if none parses.
Common mistakes
  • Models love ```` ```json ```` fences — strip them before json.loads.
  • Trailing commas & single quotes break json.loads — prefer the model's native structured-output mode over regex-scraping.

Error Handling & Retries

Supporting
try/except/else/finallycustom exceptionsexponential backoff + jittertenacityidempotency
Mental modelOn every failure ask one question: can the agent recover from this, or must the loop stop?

APIs return 429s (rate limit), 529s (overloaded), and timeouts. Distinguishing recoverable ("feed the error back, let the agent retry") from fatal ("stop the loop") is the difference between a demo and something that runs unattended overnight.

DrillHand-write a retry decorator (no library) that retries an async fn 4× with backoff (1,2,4,8s + random jitter), only on RetryableError, re-raising FatalError immediately.
Common mistakes
  • Retrying non-idempotent calls (a create/charge) can duplicate side effects.
  • Retrying 4xx client errors is pointless — only 429 & 5xx are worth a retry.
  • No jitter → synchronized clients retry in lockstep (thundering herd).

HTTP & External APIs

Supporting
httpx.AsyncClientrequestsbearer authtimeoutsos.environpython-dotenv
Mental modelEvery LLM call is just one HTTP POST with a JSON body and an auth header.

Reuse a single async client across many requests for connection pooling, always set timeouts, handle non-200s, and never hardcode API keys — load them from env vars with .env in .gitignore.

DrillUse httpx.AsyncClient to POST a JSON body with an auth header + timeout to httpbin.org/anything, then parse the echoed response.
Common mistakes
  • Creating a fresh client per request throws away connection pooling.
  • No timeout = a hung request stalls the whole agent forever.
  • Logging the full request → leaking API keys into logs (mask them).

Environment & Packaging

Supporting
uv (modern standard)venvpyproject.tomluv add / uv run
Mental modelOne project = one isolated environment. Always. No exceptions.

Isolation stops dependency conflicts between projects. uv is the current fast standard — enough to add a dependency and run a script without breaking your setup.

DrillCreate a fresh uv project, run uv add httpx pydantic, and uv run a one-file script inside it.
Common mistakes
  • Installing into global Python (pip install with no venv) — pollutes every project.
  • Committing .env or a populated venv folder to git.
  • Mixing hand-run pip install with uv-managed deps — let one tool own the lockfile.
