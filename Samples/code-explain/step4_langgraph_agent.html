1@tool-decorated functions

step4_langgraph_agent.py:23-41

Same search/calculator logic as Step 3, wrapped in LangChain's @tool decorator instead of a hand-built schema dict.

ConceptSchema-from-introspection. @tool reads the function's docstring and type hints and builds the JSON schema automatically — the docstring is the description the model sees.
Why this wayThis actually fixes the problem Step 3 had — two hand-maintained structures (TOOLS, TOOL_SCHEMAS) that could silently drift. The new cost is different: the docstring is no longer just a comment for humans, it's load-bearing input the model reads to decide when to call the tool. A vague docstring makes the tool harder to use correctly, with no error telling you why.

agent.invoke(...) replaces Step 3's whole run() call; only the last message's content gets printed.

result = agent.invoke({"messages": [("user", "...")]})
print(result["messages"][-1].content)
Why this mattersresult["messages"] actually holds the entire transcript LangGraph built internally — every tool call and tool result — but the script only shows the last line of it. Nothing was skipped; it's just not printed. That's the real difference between "the framework didn't do this work" and "the framework did this work somewhere you can't see by default."

Traced end to end

Same question as Step 3: "How many residents live across Dorm A and Dorm B combined?"

  1. agent.invoke(...) hands the question to LangGraph's model node.
  2. The model calls search; LangGraph's internal tool-execution node runs it and appends the result.
  3. Control loops back to the model node; it calls calculator("480 + 320").
  4. Loops back again; this time the model returns plain text with no tool call — the conditional edge routes to END.
  5. result["messages"] now holds roughly 6 entries: the question, two tool-call/tool-result pairs, and a final answer.
  6. Output: result["messages"][-1].content — just the final answer string.

Traps

  • No [tool] ... printout. Unlike Step 3, intermediate steps aren't shown unless you print result["messages"] yourself — "not shown" isn't "didn't happen."
  • Two new dependencies — langgraph and langchain-anthropic — beyond Steps 1-3.
  • No visible MAX_STEPS. The safety cap moved from a constant you can read in this file to a framework default you'd have to look up.
  • Same eval() demo-only risk as Step 3, copy-pasted into calculator.
  • Needs ANTHROPIC_API_KEY, same fail-fast guard as earlier steps.

What to watch when you run it

From inside samples/, with your key set:

uv run step4_langgraph_agent.py

Only one line prints — that sparseness itself is the lesson.

Predict before you run it Add print(len(result["messages"])) right after the invoke() call. Guess how many messages will be in that list, then check. Getting that number right (or wrong) is the real lesson in what "hidden" means here.
