/explain · step 6

step6_service.py

The agent behind a real web service. Instead of a one-shot script, this starts a FastAPI server that runs the Step 3 agent per HTTP request — authenticated, traced, costed, guarded, and streamable.

What happens when you run it Nothing prints at startup — it stays running, waiting for requests. Then one JSON line per request: request id, model-call count, tokens, dollars, milliseconds.

The one idea it teaches Putting the same agent behind a service adds concerns a CLI script never has: validating untrusted input, authenticating the caller, knowing what each request cost, guarding against injection, bounding how long one request can run, and streaming so the user isn't watching a spinner.

Set this first, or you'll get a 503 $env:API_KEYS = "dev-key-123" before launching uvicorn, then send -H "x-api-key: dev-key-123". Anonymous calls are refused on purpose.

What it deliberately leaves out The guardrails are explicitly crude — a substring blocklist and a check for an API-key-shaped string. And note what a blocklist structurally cannot catch: injection arriving inside a retrieved document rather than the user's message, which is the attack that actually matters for agents. Treat tool output as untrusted (OWASP LLM Top 10).

Governance lives next door Redaction, audit trails and approval gates are module 6.7, in step6b_governance.py.

one request, three exit ramps

Every guard sits before the expensive step — the agent only runs once a request has already passed length, content, and (implicitly) rate checks.

1Ask / Answer models

step6_service.py:28-34

class Ask(BaseModel):
    question: str = Field(min_length=3, max_length=500)
ConceptInput validation at a system boundary — the same BaseModel/Field tool from Steps 1 and 2, now validating an HTTP request body instead of a tool call or a model's output.
Why this wayWithout a length bound, nothing stops an empty question or a 50,000-character essay that blows your token budget on one request. FastAPI returns an automatic 422 if the body fails validation — no handler code needed, the check happens before your function even runs.

2BLOCKLIST + input guardrail

step6_service.py:25, 43-45

A tuple of literal phrases checked as substrings of the lowercased question.

ConceptAn injection/deny-list guardrail — a crude first line of defense against prompt injection attempts.
Why this way — and its honest limitThe comment on line 24 says it directly: real systems need "far more." A substring blocklist is trivially bypassed by rephrasing, typos, or a different language — it only stops the most literal attempts. It's here to show where a guardrail goes in the request flow, not to demonstrate an actually robust defense.

3Async serving + timeout

step6_service.py — the /ask handler

text = await asyncio.wait_for(
    agent(body.question, on_usage=trace.record), timeout=TIMEOUT_SECONDS,
)
ConceptDon't block the shared event loop, and bound the worst-case latency.
Why this wayFastAPI's handlers share one async event loop across every concurrent request. A blocking call inside a handler freezes that loop for every other in-flight request. And without a cap, one stuck agent run holds a connection open indefinitely — wait_for gives you a clear 504 instead of a silent hang.
This used to be asyncio.to_thread(agent, ...). The Step 3 agent was synchronous, so it had to be pushed onto an OS thread to keep the loop free. That worked, but it capped concurrency at the thread pool and papered over the real problem one layer down. Now the agent is async, so you just await it — the same simplification Step 5 got. Rule of thumb: to_thread is the right tool for a blocking library you don't own; on code you do own, it's a sign the fix belongs deeper.

3bAuth, tracing, and cost · new

step6_service.py — require_api_key() and class Trace

A header check that rejects unauthenticated calls, and a small span object that accumulates tokens across the loop and emits one structured line per request.

class Trace:
    def record(self, usage):          # called once per model call
        self.calls += 1
        self.usd += cost_usd(usage, MODEL)
ConceptA span is not a mystery: an id, a timer, counters, and one JSON line. Langfuse and LangSmith log these same fields with a UI on top.
Why auth firstAn unauthenticated agent endpoint is a bill anyone who finds the URL can run up on your behalf — and each request runs a multi-call loop, so abuse is expensive fast. Worse, they also get whatever your tools can reach: an open endpoint over a retrieval store is an anonymous read API for your documents. One header check is the cheapest security control in the whole track.
The number that surprises peopleRun one question and look at model_calls in the log line — it will be greater than 1. That's the loop, and each iteration re-sends the whole history, so cost grows super-linearly with conversation length. This is why the meaningful unit is cost per question, not cost per call, and why prompt caching on the stable prefix (now in step3_agent.py) is the highest-leverage optimisation in an agent.

3cThe streaming endpoint · new

step6_service.py — /ask/stream

Returns a StreamingResponse of Server-Sent Events, yielding data: {...} lines as tokens arrive.

ConceptSSE is a plain HTTP response that never closes, carrying data: lines. For one-way output you need no WebSocket machinery at all.
Why it mattersAn agent takes seconds, so your p95 latency is your user experience. Streaming converts an eight-second wait into immediate feedback without making anything faster.
The trap that makes this genuinely different from a normal handler. If the upstream call fails after 200 tokens have been sent, you cannot return a 500 — the status line and headers left long ago, and the response is already a 200. Failures have to be delivered inside the stream as an error event. Get this wrong and the client sees a stream that simply stops, then waits forever for a completion signal that never comes. Notice too that this endpoint streams a single model answer, not the whole tool loop: streaming an agent means choosing whether the user sees tokens or tool-by-tool progress, and that's a product decision, not a technical one.

4Output filter

step6_service.py:53-54

Checks whether the agent's answer text contains "ANTHROPIC_API_KEY" or "sk-ant", and redacts the whole response if so.

ConceptOutput filtering — a guardrail on what leaves the system, symmetric to the input guardrail on what enters.
Why this wayA last-resort net in case a secret somehow gets echoed back through the agent or a tool result — not a substitute for keeping secrets away from the model in the first place. Same honesty as the input filter: a pattern match, not an exhaustive defense.

Traced end to end

POST /ask {"question": "Total residents across Dorm A and B?"}

  1. require_api_key compares the x-api-key header against API_KEYS — matches, so the request proceeds. (No header → 401. No API_KEYS set on the server → 503, because failing closed beats serving anonymously.)
  2. A Trace is created: an 8-character request id and a start timestamp.
  3. FastAPI parses the body against Ask — 3 ≤ len(question) ≤ 500 passes.
  4. Lowercased question checked against BLOCKLIST — no match, guardrail passes.
  5. await asyncio.wait_for(agent(question, on_usage=trace.record), timeout=60) runs the Step 3 loop — internally search → calculator → final text — while the event loop stays free for other requests. Each model call inside that loop fires trace.record().
  6. Finishes in a few seconds, well under the cap.
  7. Output filter checks for API-key substrings — absent, text passes through unchanged.
  8. One log line: {"request_id":"a3f1…","route":"/ask","outcome":"ok","model_calls":3,"tokens_in":2841,"tokens_out":190,"usd":0.011,"ms":4820} — note model_calls: 3 for one question.
  9. Response: {"answer":"800 residents live across Dorm A and Dorm B combined.","request_id":"a3f1…","usd":0.011,"ms":4820} — the id and cost are returned to the caller too, so a support ticket can be tied to a log line.

Traps

  • This is a persistent server, not a one-shot script. Run uvicorn in one terminal and curl from a second — unlike every previous step.
  • A question under 3 or over 500 characters gets an automatic 422 — that error handling was never written by hand; it's what Field(min_length=..., max_length=...) buys for free.
  • A request past the timeout returns 504 — the timeout working as intended, not a crash.
  • Both guardrails are "crude" by the file's own admission — don't copy them into a real project as-is.
  • Needs both ANTHROPIC_API_KEY and API_KEYS set in the environment the uvicorn process is launched from. Missing the second gives you a 503, not a silent open door.
  • A 401 means you forgot -H "x-api-key: ...". That's the guardrail, not a bug.
  • Streaming errors never arrive as HTTP errors. If /ask/stream fails mid-response you get a 200 with an error event in the body — check the stream contents, not the status code.
  • Use curl -N on the streaming endpoint. Without it curl buffers and you'll see the whole thing arrive at once, which looks exactly like streaming being broken.
  • Like Steps 3 and 5, imports step3_agent — must run from inside samples/.

What to watch when you run it

Two terminals, from inside samples/:

$env:API_KEYS = "dev-key-123" uv run uvicorn step6_service:app --reload curl -s localhost:8000/ask -H "content-type: application/json" -H "x-api-key: dev-key-123" -d "{\"question\":\"Total residents across Dorm A and B?\"}" curl -N localhost:8000/ask/stream -H "content-type: application/json" -H "x-api-key: dev-key-123" -d "{\"question\":\"What are the quiet hours?\"}"

Watch the JSON response body, and — more interestingly — the structured trace line in the uvicorn terminal.

Predict before you curl 1. Drop the x-api-key header — which status code? 2. Send a question containing "ignore previous instructions" — normal answer, or 400? 3. Send "hi" — what does Field(min_length=3) return? 4. Hardest: in the trace line for one question, what will model_calls be — and can you say why before you look?
Then make the cost visible Ask a one-hop question ("What are the quiet hours?") and note the usd figure. Now ask a two-tool question ("Total residents across Dorm A and B?") and compare. The gap is the loop re-sending its history — and that gap is what prompt caching and right-sized models exist to close.
